# V-ORD-08 — отмена и журнал заказов

PATCH owner/staff `/venues/{venueID}/orders/{orderID}` сохраняет прежние `status` и `expected_status`. Для `cancelled` обязательна `reason`: `guest_request`, `unavailable`, `duplicate`, `kitchen_issue`, `other`. Необязательный `comment` — до 500 Unicode-символов. Для других переходов причина/комментарий не принимаются.

Отменять могут owner, manager и официант (с 10.11.2026, V-SRV-01; ролей kitchen и viewer больше нет). Авторизация повторяется под блокировкой. Платежи, оплаченные чаевые и неоткрытый bill запрещают отмену. API карточки и очереди возвращает `cancellation_blocked=payment_or_closed_bill` для этих ролей, чтобы показать объяснение без доступной кнопки.

Миграция 000023 добавляет order_status_events. Переход, корректировка bill/tips и запись события выполняются в одной транзакции. Повтор уже применённого перехода — no-op, событие не дублируется. Событие хранит предыдущий/новый статус, ID и снимок имени сотрудника, причину, комментарий и серверное время. Старым заказам события не выдумываются. Журнал отражает новые переходы через ordering.UpdateStatus; автоматическая отмена брони в модуле reservations не является действием этого экрана.

GET карточки возвращает `status_events` в хронологическом порядке. Список очереди не загружает журналы всех заказов. Проверка доступа к заведению выполняется до чтения. Кухонный JSON исключает журнал сотрудников вместе с финансовыми и личными данными. Клиент запрашивает журнал выбранного заказа при открытии и изменении статуса/updated_at. Гостевые API не возвращают внутренние комментарии отмены.

## Ручная проверка

1. Открыть активный заказ владельцем или менеджером. Нажать «Отменить заказ».
2. Без причины подтверждение недоступно. Выбрать причину, добавить комментарий, подтвердить.
3. Проверить отменённый статус и блок «Журнал изменений»: автор, время, переход, причина и комментарий.
4. Открыть тот же заказ другим разрешённым сотрудником и проверить состояние после синхронизации. Гостю обновляется статус без внутреннего журнала.
5. Проверить официанта: отмена предлагается и выполняется с причиной; посторонний пользователь получает 404.
6. На заказе с оплатой или закрытым счётом увидеть объяснение; отмена недоступна.
7. Два параллельных одинаковых запроса отмены дают одно событие и одну корректировку суммы. Проверено интеграционным тестом в отдельной БД.

Возврат денег, замена блюд и новые способы оплаты в эту задачу не входят.
