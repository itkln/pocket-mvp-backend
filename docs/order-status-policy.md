# V-ORD-01: состояния заказа и права

Доступ определяется владельцем или активной записью venue_staff с user_id. Приглашённый, удалённый и неактивный сотрудник доступа не имеет. Права других модулей не расширяются.

| Роль | Действия |
| --- | --- |
| owner, manager, waiter | Чтение, все допустимые переходы, отмена |

С 10.11.2026 (V-SRV-01, миграция 000025) кухня в Pocket не участвует: официант получает все заказы и передаёт их на кухню вне системы. Ролей kitchen и viewer нет; бывшие сотрудники с этими ролями стали неактивными официантами.

Для dine_in, preorder и существующего online: new → preparing («Готовится», передан на кухню) → served («Отдан») → completed. Самовывоза нет. Отмена доступна до completed; финальные состояния нельзя возобновить. Подача и завершение не создают платёж и не закрывают счёт. Статусы, каналы и права ролей определены в internal/modules/ordering/status.go.

PATCH /api/v1/owner/venues/{venueID}/orders/{orderID} сохраняет прежний маршрут с доступом по роли. JSON содержит обязательные status и expected_status, например {"status":"served","expected_status":"preparing"}. expected_status — монотонный токен конкурентности: переходов назад нет. Несовпадение исходного состояния или недопустимый переход даёт 409 с error.code=order_status_conflict и current_status. Запрещённое действие роли — 403; чужое заведение/отсутствующее членство — 404. Повтор текущего целевого статуса возвращает успех без UPDATE, изменения timestamps и финансовых эффектов. Повтор после дальнейшего продвижения — 409.

Транзакция повторно проверяет роль и блокирует заведение/членство FOR SHARE, затем заказ FOR UPDATE и счёт FOR UPDATE. Сохраняется порядок order → bill отмены брони. SQL запрещает изменение заказа отменённой брони. Отмена сохраняет проверки платежей, оплаченных чаевых и закрытого счёта; суммы корректируются только при первой отмене.

Существующий клиент владельца отправляет expected_status. Backend и клиент развёртываются вместе: старый PATCH без поля получает 422. Подключение staff-экранов — V-ORD-05, пагинация и расширенный API — V-ORD-02.

Проверки: policy_test.go (матрица ролей/статусов, stale/replay, удалённые статусы), order_policy_integration_test.go (PostgreSQL, членства, гонки, replay timestamps), orders_without_kitchen_migration_test.go (перенос данных 000025), существующие gratuity, reservation cancellation/preorder и table orders. Интеграционные тесты используют отдельные схемы базы с суффиксом _test.
