# V-ORD-09: история заказов

Вкладка «История» использует серверную выборку завершённых и отменённых заказов. Активная очередь продолжает обновляться независимо.

GET /api/v1/{owner|staff}/venues/{venueID}/orders?scope=history

Фильтры: number (точный номер), table (идентификатор стола без учёта регистра), date_from/date_to (YYYY-MM-DD, включительно), status (completed/cancelled), channel. Период относится к created_at: начало выбранного дня включительно, начало следующего за date_to дня исключительно, в timezone заведения. Проверяются формат дат и порядок границ.

Пагинация по (created_at,id), по убыванию; курсор связан со всеми фильтрами и заведением. Размер страницы UI — 50, серверный максимум — 100. Номер ищется по всей истории, не только по загруженной странице. Исторические данные блюд читаются из order_items, суммы, валюта и чаевые — из orders. Изменения меню не переписывают эти снимки.

Подробности переиспользуют карточку заказа и журнал V-ORD-08. На телефоне возврат сохраняет фильтры и положение списка; финальные заказы не имеют действий изменения статуса. Экспорт/печать не входят в задачу.

Проверка: создать/завершить тестовые заказы; открыть Историю; выбрать период, номер, стол, статус и источник; загрузить ещё; открыть карточку и вернуться. Отдельно проверить локальную полночь и поиск заказа за пределами первых 200 записей.
