# V-ORD-11 — ожидание кухни

Настройки принадлежат заведению (`venue_order_alert_settings`, миграция 000024). GET `/api/v1/{owner|staff}/venues/{venueID}/order-alert-settings` доступен владельцу и действующим сотрудникам. PUT через owner endpoint разрешён только фактическому владельцу, с повторной проверкой под блокировкой транзакции. `can_edit` определяется сервером, входное значение не даёт прав.

По умолчанию: 10 минут / #F59E0B, 20 минут / #EF4444. Пороги целые, положительные, строго возрастающие, максимум 1440. Цвет — #RRGGBB. Наибольший достигнутый порог побеждает; цвет текста выбирается по яркости фона.

Отсчёт: placed_at (или created_at) для заказа за столом. Для предзаказа — max(поступление, время визита минус preorder_lead_minutes). Поскольку отдельного плана приготовления в модели нет, добавлена общая настройка опережения для заведения: 30 минут по умолчанию, диапазон 0–1440. Она также определяет переход из группы «Ко времени» в текущую очередь.

Таймер работает только в new/accepted, независимо от открытия карточки. preparing/ready/served/completed/cancelled и отменённая бронь не подсвечиваются. Будущий предзаказ не считается ожидающим. Рядом показано количество минут ожидания. Расчёт обновляется каждую секунду; настройки сотрудников — при синхронизации очереди (5 секунд). При отсутствии сети таймер продолжает идти по последним настройкам, штатный индикатор показывает потерю соединения. Системные часы устройства должны быть корректными.

Владелец: Заказы → значок настроек «Ожидание кухни». Форма показывает оба порога, цвета с предпросмотром и опережение предзаказа. Ошибка сохранения оставляет форму открытой.

Проверки: пороги 9/10/20 минут, принятие без сброса таймера, начало готовки, будущий/поздно поступивший предзаказ, собственные цвета, контраст текста; сохранение и валидация формы; серверные права, изоляция заведений, сохранение и чтение сотрудниками.
